Forms

Form controls have a style without classes. ez-ui only adds the group of each field, with its help text and its error message, and the errors of the whole form are shown with an alert.

Field

Each field goes in an ez-field, which separates it from the next one: the label, the control and, if needed, a help text (ez-field__hint). The for of the label is the id of the control: clicking the label activates the control, and a screen reader reads the label when it reaches it. aria-describedby also tells it where the help text is.

Between 3 and 30 characters.

Controls

Text fields, drop-down lists and text areas take the whole width of the form and have the same look. The type of the <input> (email, password, number) changes the keyboard on a phone and what the browser accepts.

Every <form> is at most 42rem wide, so that the fields do not stretch from side to side on a wide screen. It is a rule without a class, so it applies to all of them; if a form needs another width, it is changed with a rule in your own stylesheet (see Customization):

Disabled

With disabled, the control cannot be used and its value is not sent with the form.

Errors

Depending on what it affects, an error is shown in a different place: under its field, above the whole form or, if it is just a passing message, in a notification.

In a field

A wrongly written value, such as an amount below the minimum. ez-field__error shows the message under the control, and aria-invalid="true" in the control draws it with a red border and tells screen readers that it is wrong.

The minimum bid is the starting price: €1,200,000.

In the whole form

An error that is not of a given field, such as the one of the API when the form is sent (the transfer market has already closed, there is no connection), goes in an error alert above the form. role="alert" makes screen readers announce it as soon as it appears.

The bid could not be registered: the transfer market has already closed.

A passing message

What only tells what has happened («Bid registered») and does not have to be corrected goes in a notification, which closes by itself. An error that the user has to read calmly to correct it, does not: it would disappear too soon.
