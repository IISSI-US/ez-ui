Customization

How the classes and the variables of ez-ui are named, and how they are adapted to the project without touching its files: from a color for the whole page to a rule for a few components.

Names of the classes

The classes follow the BEM convention (block, element and modifier): the name of a class says which component it belongs to and what role it has in it. All of them start with ez-, to tell them apart from the project's own.

  • Component: its name (ez-card, ez-button).
  • Part of a component: the name of the component, two underscores and the name of the part (ez-card__body). It only makes sense inside its component.
  • Variant: it is added to the class of the component, with two hyphens, and changes its look without repeating the rest (ez-button ez-button--danger).

ez-card gives the frame of the card (border, shadow and background), and ez-card__body, the padding that separates the content from the border; that is why the content goes inside the body.

The project's classes have another prefix, or none. They can go together on the same element: ez-card gives it the look of a card, and player-card says that it is a player's card.

Your own stylesheet

The changes go in a stylesheet of the project, linked after ez-ui. The files of ez-ui/ are not modified: that way the folder can be replaced by a new version without losing anything.

When two rules give a value to the same property of an element, the one with the more specific selector wins (an id weighs more than a class, and two classes more than one) and, if they are equally specific, the one that comes later. That is why your own stylesheet goes after it: with the same selector as ez-ui, its rule wins.

If a rule is not applied, the developer tools of the browser (Elements tab, Styles panel) show which other rule strikes it out.

Variables

The colors, the fonts, the spacing and the radii of the corners are CSS variables that start with --ez-, defined in :root (the <html> element) in tokens.css. The other stylesheets use them with var(), so giving them another value in your own stylesheet changes all the components that use them:

Dark theme

The dark theme does not change any rule of the components: it only gives other values to the same variables when <html> has the attribute data-ez-theme="dark", which the theme button sets.

That is why, when a color is changed, its value for the dark theme has to be given too. :root[data-ez-theme="dark"] is more specific than :root: without this rule, the dark theme would keep the color of ez-ui.

Fonts

ez-ui brings its fonts in ez-ui/fonts/, with the free OFL license: Source Sans 3 (regular and italic) for the text and JetBrains Mono for the code. They do not depend on any external service, such as Google Fonts: they work offline.

@font-face declares a font: it links a family name to a file (fonts.css does it). font-family uses it: base.css sets var(--ez-font) on <html>, from which the other elements inherit it, and var(--ez-font-mono) on code, pre and kbd.

WOFF2 is the compressed font format for the web. They are variable fonts: a single file has all the weights (font-weight: 200 900). font-display: swap shows the text with a system font while the project's own is downloaded, and the next ones in the list (system-ui, sans-serif) are used if it does not load.

Other fonts

It is enough to change the two variables in :root. Changing them inside an element does not work: <html> computes its font with the variable, and the others inherit that font already computed.

A font that is not in the system is declared with @font-face in your own stylesheet, with the file in a folder of the project, and is put first in --ez-font:

The path of url() is relative to the CSS file that contains it, not to the page: from css/app.css, ../fonts/ is the fonts/ folder of the project. For the same reason, ez-ui/css/ and ez-ui/fonts/ have to stay together. In the developer tools, the Computed panel of a text shows which font it is drawn with; if the system one appears, the Network tab says whether the .woff2 has given a 404 error.

If the same is needed in different elements, better a class of the project that is added where it is needed, such as .app-centered. The style attribute changes it too, and it is the quickest way to try something in the browser, but it cannot be reused and it stays mixed with the HTML.

The fixed navigation bar

ez-ui does not fix the navigation bar at the top, because not all applications want it: on a phone it takes up part of the screen. A rule in your own stylesheet keeps it fixed when the page is scrolled, as in this site:

sticky leaves the bar in its place until it reaches the top edge (top: 0), and there it stays; z-index puts it above the content that passes below. It stays fixed while the element that contains it is seen, so the bar goes directly in the <body>.

Icons

ez-ui brings no icons: each application chooses its own, and its components work with text only. The simplest is Font Awesome, which is linked from a CDN (a public file server) in the <head> of each page, as this site does:

Each icon is an <i> tag with two classes: the style (fa-solid) and its name (fa-plus), which is looked up in their site. It takes the size and the color of the text around it, also inside a button or with the dark theme:

A screen reader reads the page aloud to whoever cannot see it. An icon next to a text adds nothing for it, so it has aria-hidden="true" to be skipped. A button that only has the icon needs a name, in aria-label.
