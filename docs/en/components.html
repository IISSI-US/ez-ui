Components

Pieces of interface that are turned on with an ez- class, from the simplest to the most complete. The last ones combine the first ones.

Badge

A highlighted word or abbreviation inside the text: the position of a player, the state of a match. It is written with a <span>, and a second class with two hyphens changes its color.

Inside a text

Its size is relative to that of the text around it (em), so it works the same in a heading as in a paragraph.

Button

The ez-button class gives the look of a button to a <button> or to a link. <button> is used for actions (bidding, selling) and <a> to go to another page, even if they look the same. In a <button> its type is given: type="submit" sends the form and type="button" does nothing by itself.

See the transfer market

Variants

As in the badge, a second class changes the color according to the kind of action: secondary, dangerous or successful.

Disabled

With the disabled attribute, the button does not respond and looks lighter. It can be enabled and disabled from JavaScript with button.disabled = true.

With a badge

A badge inside the button shows a piece of data that goes with the action.

Alert

A message that stays in the page until it changes: an error when loading the data, the errors of a form. The left border and the background say whether it is information, success, a warning or an error. Errors have role="alert" so that screen readers announce them as soon as they appear.

The transfer market closes on Friday at 21:00.
Your lineup is confirmed for matchday 11.
You have one lineup change left this matchday.
You do not have enough money for this bid.

With more content

Inside an alert there can be a heading, a paragraph or a button.

Lineup incomplete. A goalkeeper and a defender are missing for matchday 12. Complete the lineup

For a short message that goes away by itself («Bid registered»), a notification is better: see JavaScript.

Avatar

An image cropped in a circle, for the photo of a person. If the image is not square, it is cropped without being distorted. The alternative text is left empty (alt="") when the name already appears next to it: that way a screen reader does not read it twice.

Irene Campos

Another size

The size is a variable, --ez-avatar-size (by default, 2rem), which can be changed in a given element with the style attribute, without writing another rule.

Card

It groups the information of an item (a player, a team, a match) in a block with a border and a shadow. It is written with an <article>, because each card makes sense by itself, and it has three parts, all of them optional: the image (ez-card__image), the body (ez-card__body) and the footer (ez-card__footer). Any content goes inside each part, also the previous components.

Image and body

The image is cropped to keep the 4:3 ratio without being distorted (aspect-ratio and object-fit: cover): all the cards of a list have an image of the same size.

Navigation bar

The header with the name of the application and the links to its pages. It is written with <nav> and a list of links (<ul>), which Flexbox puts in a row. On a narrow screen, the links that do not fit go to the next line (flex-wrap: wrap); if there are many, they can be folded under a button with the collapsible menu.
