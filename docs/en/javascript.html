JavaScript

Five components that need JavaScript, from the simplest to the most complete: the collapsible menu of the navigation bar, the theme button, a notification, a loading indicator and a confirmation dialog. Each one is a module of ez-ui/js/ that is imported with import from another module.

Collapsible menu

On a narrow screen, the navigation bar shows a «Menu» button and hides the links until it is clicked. The button has aria-expanded, which says whether the menu is open, and aria-controls, with the id of the list of links. On a wide screen, the button is not seen and the bar is the usual one.

ezNavbar(bar) connects the button: when it is clicked, it switches aria-expanded between "false" and "true". The CSS does the rest: while it is "false", it hides the links. If it does not receive the bar (because querySelector does not find it, or because it is not in the page yet) or the bar has no button, it throws an error that says so in the console.

Light and dark theme

A button that switches the page between the light and the dark theme. It has two parts, and the CSS shows one of them depending on the theme: ez-theme-toggle__to-dark with the light one and ez-theme-toggle__to-light with the dark one. Each one holds text, an icon or both (see Customization). Try it: it changes this whole site, like the one in the header.

ezThemeToggle(button) connects the button: when it is clicked, it changes data-ez-theme in <html> and saves the choice in localStorage, which the browser keeps when another page is opened and when it is closed. Which part is seen is chosen by the CSS, depending on the theme.

When each page is loaded, theme-init.js applies the saved theme. It is a classic script (without type="module") in the <head>, before the stylesheets: it runs as soon as the browser reads it, before the page is drawn. A module runs later, and the light theme would be seen for a moment.

Notification

A short message in a corner of the screen, which closes by itself after four seconds: «Bid placed», «Sale cancelled». For a message that the user has to read calmly, such as the errors of a form, better an alert.

ezToast(message, type, duration) creates the notification with the DOM and adds it to the page. The type is "info", "success", "warning" or "error", and the duration, the milliseconds that it takes to close (with 0, it does not close by itself). Both are parameters with a default value ("info" and 4000): if they are not passed, they take that value.

Loading indicator

It shows that something is loading while the response of the API arrives, in the same place where the data will appear. An element with the attribute aria-busy="true" shows a spinning circle, and screen readers know that its content is being updated.

    ezLoading(element, promise) sets aria-busy on the element, waits for the promise (the request) and removes it when it ends, also if the request fails. It returns the result of the promise, so it is used with await in the same place where the response would be awaited.

    Dialog

    It asks for confirmation before an action that cannot be undone, such as selling a player. It is a <dialog> element of HTML itself: the browser shows it above the page, darkens the background and closes it with the Escape key. Its buttons go in a <form method="dialog">, which closes the dialog when any of them is clicked; the value attribute of the button says which one it was.

    Sell Mario Gil?

    You will receive €400,000 and he will no longer be in your squad.

    ezConfirm(dialog) opens the dialog and returns a promise that is fulfilled when it is closed: with await, the code waits until the user chooses, and receives true if they clicked the button with value="confirm". It is an alternative to confirm(), which cannot be adapted to the look of the application.
